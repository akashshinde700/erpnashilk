    27→## API CONTRACT (all agents MUST follow)
    28→
    29→- Route files under `src/app/api/<resource>/route.ts` and optional `src/app/api/<resource>/[id]/route.ts` (Next 16: `{ params }: { params: Promise<{ id: string }> }` — await it).
    30→- Every handler wraps logic in try/catch → `return handleError(e)`; success → `return ok(data, 'msg')`.
    31→- Tenant: GET takes `?companyId=`; POST/PATCH/DELETE take `companyId` in body. Use `companyRequired(req)` (GET) / `companyRequired(req, body.companyId)` (mutations). All queries MUST filter by companyId (tenant isolation).
    32→- Transactions: any operation touching stock or multiple tables uses `db.$transaction(async (tx) => {...})`; doc numbers via `nextDocNumber(tx, ...)`.
    33→- Dates arrive as ISO strings — convert `new Date(str)`.
    34→- Money/qty round with `r2()`.
    35→- Audit every important action with `logAudit`.
    36→- GET list returns `{ items, total }` (or plain object for singletons/dashboard). Include related names (e.g. `customer: {select:{name:true}}`, `items: {include:{item:{select:{code,name,uom}}}}`) so UI can render without extra calls.
    37→- Status transitions (server-enforced, reject invalid with ApiError):
    38→  - Enquiry: OPEN → QUOTED/WON/LOST/CLOSED
    39→  - Quotation: DRAFT → SENT → APPROVED/REJECTED; APPROVED → CONVERTED (on SO create)
    40→  - SalesOrder: DRAFT → CONFIRMED → IN_PRODUCTION → READY/PARTIALLY_DISPATCHED → DISPATCHED → COMPLETED; CANCELLED
    41→  - DeliveryChallan: DRAFT → DISPATCHED (posts stock out of warehouse, increases SO item dispatchedQty)
    42→  - SalesInvoice: UNPAID → PARTIALLY_PAID → PAID; CANCELLED. Payment(RECEIPT) against invoice increments paidAmount & fixes status.
    43→  - PurchaseRequisition: PENDING → APPROVED/REJECTED; APPROVED → CONVERTED (on PO create) / CLOSED
    44→  - PurchaseOrder: DRAFT → PENDING_APPROVAL → APPROVED (sets approvedBy/At) → PARTIALLY_RECEIVED/RECEIVED (GRN post) → INVOICED; CANCELLED
    45→  - Grn: PENDING_QC → POSTED (stock in acceptedQty @ PO rate; rejected qty NO stock; creates INCOMING QcInspection PENDING; updates PO receivedQty/status)
    46→  - PurchaseInvoice: UNPAID → PARTIALLY_PAID → PAID. Payment(PAYMENT) against PI.
    47→  - WorkOrder: PLANNED → RELEASED → IN_PROGRESS (first material issue or production entry) → COMPLETED (produced+rejected >= planned) ; CANCELLED
    48→  - MaterialIssue: POSTED (stock out from RM warehouse = WO.warehouseId? NO — issue uses warehouse chosen in request; validate availability, block over-issue beyond requirement+5%; sets WO IN_PROGRESS)
    49→  - ProductionEntry: posting adds producedQty to WO + PRODUCTION_IN stock (rate = item.standardCost) to WO.warehouseId; auto-completes WO when produced+rejected >= planned; WO number as refType.
    50→  - QcInspection: PENDING → PASSED/FAILED/PARTIAL (stores qtyAccepted/qtyRejected, parameters JSON array [{name,expected,actual,ok}])
    51→  - Stock transfer: TRANSFER_OUT + TRANSFER_IN rows; adjustment: ADJUST_IN/ADJUST_OUT with reason.
    52→  - Item create: optional openingQty+openingRate → OPENING stock post to given warehouseId.
