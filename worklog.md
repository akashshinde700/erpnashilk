## API CONTRACT (all agents MUST follow)

- Route files under `src/app/api/<resource>/route.ts` and optional `src/app/api/<resource>/[id]/route.ts` (Next 16: `{ params }: { params: Promise<{ id: string }> }` — await it).
- Every handler wraps logic in try/catch → `return handleError(e)`; success → `return ok(data, 'msg')`.
- Tenant: GET takes `?companyId=`; POST/PATCH/DELETE take `companyId` in body. Use `companyRequired(req)` (GET) / `companyRequired(req, body.companyId)` (mutations). All queries MUST filter by companyId (tenant isolation).
- Transactions: any operation touching stock or multiple tables uses `db.$transaction(async (tx) => {...})`; doc numbers via `nextDocNumber(tx, ...)`.
- Dates arrive as ISO strings — convert `new Date(str)`.
- Money/qty round with `r2()`.
- Audit every important action with `logAudit`.
- GET list returns `{ items, total }` (or plain object for singletons/dashboard). Include related names (e.g. `customer: {select:{name:true}}`, `items: {include:{item:{select:{code,name,uom}}}}`) so UI can render without extra calls.
- Status transitions (server-enforced, reject invalid with ApiError):
  - Enquiry: OPEN → QUOTED/WON/LOST/CLOSED
  - Quotation: DRAFT → SENT → APPROVED/REJECTED; APPROVED → CONVERTED (on SO create)
  - SalesOrder: DRAFT → CONFIRMED → IN_PRODUCTION → READY/PARTIALLY_DISPATCHED → DISPATCHED → COMPLETED; CANCELLED
  - DeliveryChallan: DRAFT → DISPATCHED (posts stock out of warehouse, increases SO item dispatchedQty)
  - SalesInvoice: UNPAID → PARTIALLY_PAID → PAID; CANCELLED. Payment(RECEIPT) against invoice increments paidAmount & fixes status.
  - PurchaseRequisition: PENDING → APPROVED/REJECTED; APPROVED → CONVERTED (on PO create) / CLOSED
  - PurchaseOrder: DRAFT → PENDING_APPROVAL → APPROVED (sets approvedBy/At) → PARTIALLY_RECEIVED/RECEIVED (GRN post) → INVOICED; CANCELLED
  - Grn: PENDING_QC → POSTED (stock in acceptedQty @ PO rate; rejected qty NO stock; creates INCOMING QcInspection PENDING; updates PO receivedQty/status)
  - PurchaseInvoice: UNPAID → PARTIALLY_PAID → PAID. Payment(PAYMENT) against PI.
  - WorkOrder: PLANNED → RELEASED → IN_PROGRESS (first material issue or production entry) → COMPLETED (produced+rejected >= planned) ; CANCELLED
  - MaterialIssue: POSTED (stock out from RM warehouse = WO.warehouseId? NO — issue uses warehouse chosen in request; validate availability, block over-issue beyond requirement+5%; sets WO IN_PROGRESS)
  - ProductionEntry: posting adds producedQty to WO + PRODUCTION_IN stock (rate = item.standardCost) to WO.warehouseId; auto-completes WO when produced+rejected >= planned; WO number as refType.
  - QcInspection: PENDING → PASSED/FAILED/PARTIAL (stores qtyAccepted/qtyRejected, parameters JSON array [{name,expected,actual,ok}])
  - Stock transfer: TRANSFER_OUT + TRANSFER_IN rows; adjustment: ADJUST_IN/ADJUST_OUT with reason.
  - Item create: optional openingQty+openingRate → OPENING stock post to given warehouseId.
